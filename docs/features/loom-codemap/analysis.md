# Goal Description

Migrate the Context Engineering codemap feature from the existing bash script (`scripts/generate-codemap.sh`) to a native Go CLI command (`loom codemap` or `loom map`). This command will process a repository, respect ignore rules, and create LLM-optimized map artifacts (Markdown and JSON) of the structure, locations, and purposes of directories and files to minimize LLM token churn.

## User Review Required

> [!IMPORTANT]
> **Command Naming & Formatting**: The proposal defaults to `loom codemap` (to match the existing artifact naming of `CODEMAP.md`) and outputs both `CODEMAP.md` and `codemap.json` by default. Do you prefer `loom map` instead, and are you aligned with generating both JSON (for RAG/MCP ingestion) and Markdown (for human/LLM readability)?

## Open Questions

> [!WARNING]
> **File-Level Granularity**: The bash script currently maps up to depth-2 directories by reading `README.md` files. For the native command, do we want to immediately implement file-level parsing (e.g. extracting Go package docstrings or JS/TS file headers), or should phase 1 purely replicate the bash script's directory-level behavior in Go, adding file-level parsing in a later iteration?

### Output Generation

#### [NEW] [internal/codemap/formatter.go](file:///Users/oscarrieken/Projects/Rieken/ai-assistant-dot-files/internal/codemap/formatter.go)
- `FormatMarkdown(tree)`: Builds the `CODEMAP.md` tree.
- `FormatJSON(tree)`: Builds the `codemap.json` output containing a flat or nested array of objects: `{"path": "cmd/loom", "type": "dir", "purpose": "loom CLI"}` for optimized RAG injection.
