### Agent prose consistency after L3.50

Checked because L3.50 changed the `tools:` line on seven agents, which is exactly the change that
strands a description.

- `docs/AGENT_REFERENCE.md` describes agents with **Role / Counterbalance / Gap** and carries no
  per-agent `Tools` line, so the tool change stranded nothing there. Worth recording because the
  auditor's own prompt says to check agents are listed "with description and tools" — that criterion
  does not match how this document is actually structured, and reading it literally would produce 40
  false findings.
- `accessibility-engineer`'s Role still reads *"fixes objective violations directly"*
  (`AGENT_REFERENCE.md:135`). That was the prose describing behavior the agent had no tool for; after
  L3.50 it declares `Edit`, so the sentence is now **true where it previously was not**. No change
  needed.
- The claim that `tools` *"enforces capability boundaries"* survives only in historical records —
  `BUILD-ROADMAP.md`, `shared/agents/CHANGELOG.md`, the alignment TODO and `security-patterns.md` —
  each describing the correction rather than repeating the claim. The three live sources
  (`agent-frontmatter-contract.md`, `frontmatter-conventions.md`, `agent-frontmatter.schema.json`)
  were corrected in L3.50.
