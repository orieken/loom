# AI Platform Onboarding

Welcome! This repository defines one canonical set of AI agents, skills, and rules — written once in
`shared/`, then generated or symlinked into whatever AI coding tool you actually use — Claude Code, Cursor,
Windsurf, GitHub Copilot, Gemini/Antigravity, OpenAI/Codex, JetBrains AI Assistant + Junie, Roo Code, and
Cline. See
[AGENT_REFERENCE.md](AGENT_REFERENCE.md) for the full agent list,
[ARCHITECTURE.md](ARCHITECTURE.md) for the canonical skill and platform inventory, and
[README.md](../README.md) for the framework overview.

## Install this first

```bash
brew install orieken/tap/loom     # or: go install github.com/orieken/loom/cmd/loom@latest
loom install --dry-run            # see exactly what would be written
loom install                      # auto-detects which AI platforms you have
```

`loom install --target /path/to/project` installs into one project instead of the current directory, and
`--platform claude` forces a single platform. Symlinks are the default — add `--copy` for an install that
does not depend on this repo's checkout staying put (required on Windows without WSL). `loom health`
verifies an install, and `loom uninstall` removes it. See `cmd/loom/README.md` for the full command
reference.

The older `./install.sh` still works and is the fallback where the binary is unavailable, but `loom` is the
primary path.

For an interactive walkthrough instead of reading this file, invoke the **`onboard`** skill
(`shared/skills/onboard/SKILL.md`) in an active session, or type `/onboard` — it explains rules/agents/skills, shows how to
invoke an agent and trigger a skill, and walks through running a full pipeline delivery.

## Where things actually live
`shared/agents/`, `shared/skills/`, and `shared/rules/` are the single source of truth — edit there, never in
a generated platform config. For Claude Code specifically, `.claude/agents/`, `.claude/skills/`, and
`.claude/rules/` are symlinks into `shared/`, not a separate copy; editing through the symlink and editing
the canonical file are the same operation. Every other platform's config is generated by
`scripts/generate-configs.sh`, not symlinked, since most of those tools can't follow file references.

## Running a delivery, and what stops it

Two ways to run the pipeline. In an AI tool, invoke the `deliver-feature` skill and the model works
through the stages. Or run it as a process:

```bash
loom run --spec docs/features/user-auth/spec.md
```

`loom run` is experimental, and it differs from the skill in ways worth knowing before you use it:

- **It halts at approval gates and cannot be talked past them.** `confirm-design`, `confirm-security`, and
  `confirm-ship` are barriers in code — nothing an agent returns can open one. You approve at the prompt,
  or resume with `--approve <gate>`; a halted run exits with code 3.
- **It decides which stages your feature needs** from the analysis, records why, and shows you before the
  design gate. `loom state show` answers "why isn't devops running?".
- **It notices edits.** Artifact digests are computed and re-verified in Go, so a hand-edited artifact
  re-runs its stage — and if you edit something you already approved, the gate resets and asks again.

`loom state record|verify|show|timeline` are how the markdown pipeline records the same checkpoints
without a model computing its own checksums.

## A few agents worth knowing early
- **`spec-writer`** — interviews you to build a feature spec, critiques its own readiness before the
  pipeline runs.
- **`context-engineer`** — pre-flight context optimizer; runs before analyst on any non-trivial task.
- **`modernization-supervisor`** (`shared/agents/modernization-supervisor.md`) — coordinates parallel
  legacy-modernization workstreams (dependency updates, pattern refactors, coverage gaps).
- **`documentation-manager`** — persistent agent that extracts long-lived architectural/debugging knowledge
  from sessions over time and keeps docs like this one in sync.

Full roster and how to invoke each agent on your specific tool: see README.md's "Agent Roster" and "Using the
agents by tool" sections.

## A few skills worth knowing early
- **`list-agents`** — query the repo for all available custom AI personas.
- **`scaffold-docs`** — bootstrap a markdown implementation guide before building a large feature.
- **`deliver-feature`** — the main pipeline orchestrator.
- **`deliver-bugfix`** — lightweight 5-phase pipeline for known, reproducible bugs (reproduce-first discipline); escalates to `deliver-feature` if scope expands.
- **`on-call`** — incident response playbook; persists a permanent incident record to `docs/incidents/`.
- **`five-whys`** — root cause analysis; produces the why-chain and recommended action for an incident record.
- **`health-check`** — validates the install: symlinks, frontmatter, platform config drift, and inter-agent
  contracts. Run it when something feels wrong before you go looking by hand.
